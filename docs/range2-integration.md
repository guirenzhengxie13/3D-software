# RANGE 2 接入与验收

当前使用官方采集后的离线数据包，用户已确认解包实现，近期聚焦后处理、工作流与 Agent。SDK 接入留待项目完成后探索，本文件保留为参考清单。当前设计见 [工作流与 Agent 架构](workflow-agent-design.md)。

首个设备为 RANGE 2。当前设备不在身边，计划 2026-10-16 获取设备号后申请官方 SDK 试用。本文件是本项目的接口需求与联调方案，不是厂商 API 文档；`config/range2.example.json` 是规划清单，当前原型不会读取它。

## 软件分工

| 软件/组件 | 当前作用 | 下一步 |
| --- | --- | --- |
| Revo Scan 6 Windows x64 | 检查设备连接、标定状态、采集基准和导出 PLY | 已准备官方安装包，设备到场后安装并验收 |
| 官方 RANGE 2 SDK | 发现设备、设置采集参数、取得逐帧数据 | 索取匹配当前固件的包、文档、样例和试用授权 |
| Python + NumPy + Open3D | 点云接入验证、显示、文件回放、后续算法试验 | 本项目 `.venv` 已安装并可运行 |
| Visual Studio C++ | 若厂商只提供原生 SDK，编写采集桥接程序 | 本机已检测到 VS 2022 Community 的 x64 C++ 组件；收到 SDK 后确认 ABI |

现在不需要先装完整 Qt / PCL / CUDA。先验证 SDK 数据边界，再按交互界面与算法需求引入；也不需要为这个阶段购买逆向设计或计量软件。

## 必须拿到的信息

| 项目 | 最低需求 | 容易误解的地方 |
| --- | --- | --- |
| 设备与运行库 | 支持 RANGE 2 的 SDK/固件版本、Windows x64 DLL、头文件、lib、依赖运行库 | Revo Scan 支持该型号，不意味着旧公开 SDK 与当前固件兼容 |
| 授权 | 设备 SN、激活步骤、试用起算与过期行为、是否需联网 | 软件安装、SDK 下载与设备授权是不同步骤 |
| 帧数据 | 未融合的单帧 XYZ；或可转换 XYZ 的深度及标定 | 最终融合点云不能替代逐帧输入 |
| 深度解释 | 格式、分辨率、stride、depth scale、无效值定义、是否已校正 | 不能把所有 uint16 数据直接当毫米 |
| 坐标/标定 | 轴向、左右手、原点、单位、相机内外参、畸变处理 | RGB/depth 外参与跨帧运动位姿不是同一个参数 |
| 同步/时间 | 帧号、设备时间戳、时间单位与时钟域、RGB/depth 配对策略 | 回调到达电脑的时间不等于曝光时间 |
| 可选信息 | RGB、置信度、IMU、追踪状态、每帧相机位姿 | 设备有 IMU 不代表 SDK 开放 IMU 或完整运动估计 |
| 控制/稳定性 | 枚举有效配置、开始/停止、曝光/增益、错误码、断线恢复 | 型号宣传最高帧率不等于每种模式的可用帧率 |
| 发布许可 | SDK DLL 和 Python 包再分发、论文开源代码边界 | 公开示例代码许可不自动覆盖全部二进制 SDK |

若只有深度而无 XYZ，应优先用匹配版本的官方深度转点云函数。只有在文档确认深度已经校正、采用相应针孔模型、比例单位已知时，才可按 `Z=depth*scale; X=(u-cx)*Z/fx; Y=(v-cy)*Z/fy` 转换，并保留厂商定义的坐标方向。RGB 还需正确处理深度到彩色的外参和投影。

## 本项目的数据接口

已实现的 `PointCloudFrame` 统一保存拥有独立内存的 `xyz[N,3]`、可选归一化 `colors[N,3]`、帧号、时间戳、时钟域、坐标系名称。位置统一为米，颜色范围为 0–1；无效点应在适配器里过滤。PLY 回放必须由调用者指定米或毫米，且保留原文件轴向。

将来真实适配器还应单独记录设备采集时间与主机接收时间，以及可选原始深度/RGB、标定、位姿和状态。现有原型只实现上述基础点云契约，不声称已经实现这些扩展字段或设备回调。

未来实时路径：

```text
RANGE 2 → 官方 SDK → 采集线程/原生桥接 → 复制帧并统一单位
                                            ↓
                         有界预览队列 → Open3D/交互界面
                                            ↓
                         数据记录 → 配准/融合/辅助重建
```

采集回调中只复制必要数据并迅速返回，不能直接做重建或操作 GUI。预览队列以最新帧为主并统计丢帧，避免画面滞后；研究用原始记录应使用独立有界写盘队列并报告丢帧，不能静默丢数据。先在同一进程测试厂商支持的 Python 绑定；若 Python 版本不匹配，则用受支持的独立 Python 环境或 C++ 采集进程桥接，不能直接用 `ctypes` 猜 C++ 虚函数接口。

## 真机到场后的顺序

1. 按官方连接方式先用 USB 数据线，检查供电和系统枚举。在 Revo Scan 里确认能预览深度并导出一份点云；保存固件/软件版本和标定状态。先不要在缺少兼容依据时升级固件。
2. 关闭占用设备的扫描软件，按厂商说明激活 SDK，先运行其原版最小采集示例。保留原始错误码和日志。
3. 枚举设备与流配置，读取实际型号、帧尺寸、格式、内外参和深度比例。不要预设固定 IP、端口、USB VID/PID 或 SDK 参数值。
4. 先保存一帧有单位说明的深度/XYZ，确认坐标和量级，再连续读取并显示。建议以 60 秒采集作为首次稳定性检查，记录有效帧数、间隔、延迟、空帧、错误和丢帧；这只是本项目验收方案，不是厂商性能承诺。
5. 检查停止后资源释放及再次打开；再验证拔插、丢帧和 Wi-Fi。RANGE 2 硬件支持 Wi-Fi，不等于所有 SDK 版本都支持相同网络流程。
6. 只有上述验证通过，才把数据源换进交互重建软件。配准、融合、补洞、编辑与扫描引导单独开发。

若 SDK 等待期间需要继续开发，可用 Revo Scan 导出的真实 PLY 做离线处理；这能推进交互功能，但不能验证硬件实时链路。当前附带的 `data/synthetic.ply` 为人工合成测试数据。
