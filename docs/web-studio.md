# Web 交互辅助重建工作台

现在以本地 Web 软件作为交互入口，官方 Revo Scan 继续负责采集，输入仍是已解包的离线工程。页面和数据在本机处理，当前没有连接 Agent 模型服务。

## 启动与入口

项目根目录 PowerShell：

```powershell
& '.\scripts\start-web-studio.ps1'
```

在 Chrome 打开 **http://127.0.0.1:8877**。保持服务终端运行；Ctrl+C 停止。指定其他端口可使用 `-Port 8878`。服务只绑定本机回环地址，启动时独占端口，避免误连已有的其他本地服务。

当前顶层收拢为 **工程工作区 / 实验与证据 / 处理任务**。模型、保存帧、对应点是同一工程下的三种工作模式；从实验或任务返回时保留该模式。原始研究页面保留在折叠入口，不再作为并列软件分支。

不直接双击 `web/landmark-workbench/index.html`：它是没有内嵌模型的开发模板，已增加明确提示。Web 工作台会打开 `reports` 里带实际模型数据的已生成页面。

## 当前可操作功能

| 页面 | 实际能力 |
| --- | --- |
| 模型空间 | 33份新旧扫描工程；切换完整结果的空间预览；勾选最多3层叠加；旋转、平移、缩放；显示原顶点编号；本地PLY浏览 |
| 局部查看 | 点击模型点，读取其周围球形范围的完整原顶点；先为该模型构建索引；返回概览保留完整模型引用 |
| 原始帧回放 | 解码保存深度、反投影并使用优化或保存位姿；彩色点与深度图；按保存序列手动/自动回放 |
| 对应点配准 | 初始6个研究工作台，按工程归属展示；可选择目录中两份模型建立新工作区；三视图、至少3对对应点求刚体变换、会话与后端核对 |
| 重建实验 | 22类已有实验入口及实际图片；同源官方比较、两片段融合、联合深度融合、选区、颜色、标记、转轴和失败尝试；嵌入查看或独立打开 |
| 数据与任务 | 数量和内存记录；已有五步/三步工作流；网页创建的空间缓存、索引或对齐任务；状态、日志、取消请求和持久化结果 |

模型清单还包含官方保存融合、扫描预览、主融合和实验片段。实验衍生结果是同源重复产物，不当作新采集数据计数。

## 建议的首次展示顺序

1. 打开模型空间，默认是 **2026-10-18 12:26:07 彩色人偶**的精细自研候选：完整793,214点，默认显示39,141个实际源顶点。勾选官方保存融合进行来源着色叠加；精确三色支持对照从“重建实验 → 官方融合与自研结果”打开。
2. 切到原始帧回放，查看同一工程保存的单帧深度、颜色和位姿。默认每帧最多显示25,000个实际深度像素。回放速度不代表采集帧率，文件编号也不当作时间。
3. 在对应点页选择原两片段或失败扫描的某条连接。Alt单击或点选模式选择同一物理位置，计算刚体对齐后点击 **核对并另存对齐模型**。父页面只接受当前同源工作台发来的会话，后端核对文件哈希及原始坐标，再写入新目录。
4. 到重建实验查看两片段全358帧演示、两份463帧联合深度融合和失败尝试。候选改善与剩余孔洞、重影、冲突同时保留。
5. 回到模型空间，点击 **生成空间缓存与局部索引**。任务完成后选择一个点，再点击 **查看选中点周围完整顶点**，读取该模型局部的原始点，而不是继续放大稀疏预览。

本地PLY导入需明确原文件是毫米还是米；米转换为毫米。该功能只在浏览器临时预览，不自动加入后端工程或上传文件。预览按原文件行号抽样，不能冒充空间覆盖保证。

## 空白显示的处理

工作台会显示已绑定的文件名与点数，初始化失败会给出文字信息。WebGL不可用或着色器失败时自动使用 **Canvas兼容绘制**，也可手动切换；旋转、缩放和选点仍可使用。对应点页还修正了长侧栏导致绘图区伸长的问题。

本次用户反馈后复现：目录元数据中的 `points` 是整数，旧viewer用 `row.points || decode(row.xyz)` 把它误当成坐标数组。已改为明确判断数组类型，后端几何响应也移除了该歧义字段；点数通过 `originalPoints` / `displayPoints` 返回。真实HTTP数据到实际viewer的8例检查均产生非空CPU像素，避免此前孤立HTTP和数组mock漏检。

隐藏的对应点iframe在进入该页后才加载，避免以零宽度初始化视角。Canvas兼容绘制采用实际点和逐像素深度缓冲，保留原点编号；精确求解仍由后端读取完整模型完成。

浏览器工具拒绝本地 `file://` 地址，未通过换入口或其他浏览器工具绕过。因此目前完成的是本地HTTP、生成页面控制逻辑与真实CPU像素检查，**尚未完成Chrome实机画面与GPU检查**。

## 当前边界

任意片段的对应点变换已经能核对和另存表面；接回原深度重融合还需明确每帧的片段归属，不能把任意通用PLY直接当原帧工程。当前原两组片段的重融合已有演示，通用片段桥接、统一工程撤销历史、异常帧交互选择和Agent工具调度是下一阶段。

局部取点是完整已生成表面的一部分，不能恢复扫描时没保存的深度或完全未观察到的形状。补扫方向仍是离线建议，不是设备实时引导。SDK方向保持后置。
