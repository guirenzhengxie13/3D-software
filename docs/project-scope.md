# 课题范围与首版验收

确定日期：2026-10-15。课题名称：**面向三维扫描模型的交互式辅助重建软件设计与实现**。

## 核心目标

由官方软件和扫描仪完成数据采集。本课题针对同一物体的多次扫描工程，提供可检查、可干预、可追溯的重建工作流，改善坏帧、局部失跟、重影及跨扫描对齐困难等问题。

用户已确认离线包解包能力实现。近期承接既有解包成果，主要开发扫描片段取舍、跨扫描交互配准、组合重建、高效工作流与 Agent 框架。SDK 实时接入留待本项目完成后探索。

人工操作与 Agent 共用统一后处理命令、任务执行和处理历史；设计见 [工作流与 Agent 架构](workflow-agent-design.md)。

## 首版最小闭环

同一物体至少两次扫描 → 导入并检查可用数据 → 区分来源与问题片段 → 用户排除坏片段、指定对应关系 → 辅助对齐及局部配准 → 融合重建 → 比较并导出结果与编辑记录。

| 环节 | 首版应交付的能力 | 验收方式 |
| --- | --- | --- |
| 多工程导入 | 承接既有解包输出，显示版本、设备与可用内容，保留来源 | 实际输出完成导入与清点，抽查其与官方预览的对应关系 |
| 数据检查 | 区分正常、缺失、隐藏、无法解析等状态；按扫描来源显示 | 解析失败有原因，不默默跳过再宣称完整 |
| 片段取舍 | 查看单帧/连续片段，选择参与重建的数据，操作可撤销 | 原始工程不变，可重放选择记录 |
| 跨扫描对齐 | 用户指定对应区域或对应点，调整初始位置，再进行配准 | 同一物体多包放入共同坐标，能够检查和修正错误对应 |
| 组合重建 | 根据所选数据形成点云/表面，并检查接缝、重影和低支持区域 | 与同批数据的官方处理结果及干预前结果比较 |
| 结果复现 | 导出模型，并保存选择、变换、参数和来源记录 | 重开项目能恢复相同处理状态 |
| 工作流与 Agent | 人工和 Agent 调用相同处理能力，支持预设、任务状态与结果比较 | 在相同数据上完成可追踪的处理步骤，评价任务完成与操作效率 |

第一版交互重点为 **片段取舍与跨扫描对齐**。逐帧完整解析以真实样本为准；如果某类工程暂时不能解析，可先使用官方导出点云验证跨包交互流程，明确其不包含逐帧信息，不阻塞全部软件功能。

## 数据坐标与相机位姿

每个扫描工程可能有独立坐标系，即使用同一台设备扫描同一个物体，也不能直接把各包点云叠在一起。需要分别保存帧在原工程中的变换，以及工程到统一物体坐标系的跨包变换，避免将原位姿覆盖或重复应用。

工程内矩阵先按“保存的参考系变换”处理，验证约定后再用于轨迹显示。它是算法估计，不是真值；其生成阶段也可能未知。若物体放在转台上，相机可以不动、物体持续转动，此时不能将所有相对运动直接画成相机的真实空间路径，也不能把台面与物体强行按同一个刚体对齐。

## 离线补扫建议

先提供扫描后分析：指出哪些区域未被充分覆盖、只被少数视角支持、存在重影或观察角度不佳，并在物体坐标系中给出建议观察方向。用户可根据建议再用官方软件补扫，导入新工程后重新重建，形成“重建—诊断—补扫—再次重建”的闭环；该流程不需要实时设备接口。

如果能验证视点、标定及位姿含义，再考虑回放已有视角和模拟候选扫描路径。建议视点应结合可见性与设备工作条件验证；不能仅凭空洞就断定未知表面的真实形状或保证提高绝对精度。软件中应区分未覆盖、低支持、疑似异常和算法补全结果。

实时阶段将统一输入接口接到实时帧源，增加在线位姿、覆盖更新与低延迟反馈。离线阶段可复用数据与算法结构，但不能替代对实时同步、失跟、丢帧和延迟的验证。

## 如何判断“辅助重建有效”

选择同一批扫描数据和明确的问题区域，保留官方结果、交互干预前结果与干预后结果。比较接缝重影、重叠区域残差、有效观测覆盖和完成相同任务的操作耗时。若有参考尺寸或可靠参考模型，再评价尺度或几何精度；仅有更小的重叠残差，不能证明真实几何更准确。

首版可以先展示一个代表性案例：官方跨包组合出现明显重影，用户通过片段排除和对应关系修正，得到可检查的改善，并能复现全部操作。随后再扩展不同物体、设备和失败类型。
