# 离线重建软件的工作流与 Agent 设计

范围确定于 2026-10-15：官方软件负责扫描，离线工程包是本软件的数据起点；解包能力已由用户确认实现。接下来承接已有解包成果，集中开发重建后处理、高效工作流和 Agent 辅助。SDK 实时接入留待本项目完成后探索。

本文件包含拟定架构与当前实现范围。[Web工作台](web-studio.md)已接入项目目录、模型/原始帧浏览、对应点和空间处理任务；工程撤销历史与语言模型服务层尚未实现。已有[确定性工具与任务执行原型](offline-workflow-runner.md)，实际串行完成五步扫描分析。当前也有离线数据库解析、位姿读取、TSDF 重建、跨扫描配准、三维审阅、[对应点配准原型](landmark-workbench.md)与[离线覆盖/原帧回查/观察方向建议](offline-coverage-guidance.md)。旧四份工程实测见 [记录](four-scan-experiment.md)。源码参考来自用户提供并授权访问的恢复成果，接入依据见 [既有恢复成果](recovery-integration.md)。

2026-10-19 补充：[新增扫描研究](range2-study-20261018.md) 已覆盖 29 份工程、9,434 帧、彩色与标记数据。结果提示应优先支持空间区域选择、帧阶段选择和候选比较：背景会降低当前融合的实际分辨率；标记残差降低也可能没有改善物体对齐。工具的候选输出须分别报告标记、运动和表面证据，不能只用单个分数自动合并。新工程的坐标与颜色约定由索引显式记录，界面不能硬编码旧 Y/Z 翻转或忽略红蓝通道验证。

最新同像素交叉检查显示：候选可在拟合参考上减少冲突，在另一扫描上却出现阈值敏感的支持/冲突混合；部分冲突消失只是点被前表面遮挡。评价工具应返回支持、自由空间冲突、遮挡与未定的分开计数，保留共同可观测点的成对转移、多个阈值及内部对照。Agent 不把“无冲突”自动解释为“有表面支持”，也不能在尝试后只报告最有利阈值。原始帧字段未确认语义时按偏移显示，不据此自动删帧或生成真实时间线。见 [新增研究 5.8](range2-study-20261018.md#58-换一份扫描检查并固定相同的原始深度像素)。

## 软件分层

```text
离线工程包 → 已有解包程序 → 导入适配与项目数据
                                  ↓
人工界面 ───────────────→ 统一处理命令 → 任务执行器 → 后处理计算
Agent 工具调用 ─────────→      ↑                         ↓
                         参数与上下文              新结果、进度和质量报告
                                  ↑                         ↓
                         项目状态与处理历史 ←───────────────┘
```

人工操作与 Agent 使用同一套处理能力、结果记录和错误反馈。几何计算集中在可测试的后端，界面提供观察和纠正，Agent 组织步骤并解释结果。

## 既有解包成果的衔接

先确认解包后实际提供的数据，再选择适配粒度：已有融合点云可以推进跨扫描后处理；若有逐帧点云、深度和位姿，则进一步支持片段筛选和帧级修正。帧级能力不作为所有处理功能的前置条件。

| 信息 | 接入要求 |
| --- | --- |
| 来源 | 工程包、物体、扫描次数、帧或片段的稳定标识，以及对应文件引用 |
| 几何 | 点云，或深度及相应标定；注明实际分辨率、单位和坐标系 |
| 位姿 | 有则保留原始矩阵、约定和来源，验证后用于处理；没有则明确缺失 |
| 颜色 | 可选，记录与几何的对应关系和是否已完成配准 |
| 状态 | 有效、隐藏、参与处理等标志，以已有解包结果和验证语义为准 |
| 时间 | 有则保留时钟含义；没有时使用帧序号，不伪造采集时间 |

导入层不覆盖源工程。处理所需的单位或坐标约定不明时，应先完成核对；缺失位姿不能自动填单位矩阵并当作真实估计。

## 后处理命令与执行

每条命令至少描述输入结果版本、作用对象、参数、输出和执行状态。耗时计算由任务执行器管理，支持进度、取消、失败原因和重试；界面与 Agent 查询相同状态。

拟定的首批处理能力：

| 能力 | 典型用途 | 结果 |
| --- | --- | --- |
| 数据检查 | 检查资源、点数、尺度、坐标和缺失项 | 可定位的数据报告 |
| 数据选择 | 选择扫描、帧段、空间区域及参与状态 | 独立选择记录/掩码 |
| 清理与预处理 | 去除明确异常、裁剪、生成配准预览 | 新点云版本及处理参数 |
| 初始对齐与配准 | 利用对应点、对应区域或已有变换对齐多包 | 变换、候选结果及评价 |
| 融合与表面重建 | 对选定数据生成组合结果 | 新点云/网格及来源 |
| 版本比较 | 检查接缝、重影、细节和覆盖变化 | 并排或叠加预览、局部报告 |
| 导出与项目保存 | 保存模型和可复现处理状态 | 结果文件与处理记录 |

预览可以使用降采样数据，正式结果须保留与原始输入的对应关系。不同扫描工程到统一物体坐标系的变换，与各工程内部帧位姿分开保存。

## 高效工作流

首版工作流可以围绕“导入检查 → 片段取舍 → 初始对齐 → 局部修正 → 融合 → 质量比较 → 导出”组织，同时允许用户返回任一步调整。

- 保存可复用的参数预设，对多个扫描批量处理；预览效果后再生成正式结果。
- 每个阶段保留输入引用与输出版本，方便回退、比较和重做，不反复改写原始数据。
- 选择区域、错误报告和处理历史能够定位到同一个扫描/帧段，减少在列表与三维视图之间寻找数据的时间。
- 对齐存在多个合理候选时，提供并排或叠加比较；用户修正对应关系后沿用已有流程继续处理。
- 正常的可逆步骤可连续执行；出现缺失信息、失败或几何歧义时，在相应步骤提供交互入口。

## Agent 的职责

首版采用一个 Agent 配合结构化工具和任务执行器，先验证可用性，再决定是否需要更复杂的框架或多 Agent 协作。具体模型和框架暂不绑定。

Agent 可负责：

1. 整理当前工程与选择对象，说明缺失数据和可执行步骤。
2. 将用户意图转换为明确的处理对象、参数和命令序列。
3. 推荐参数或安排少量候选试验，生成可比较的预览。
4. 汇总处理结果，定位疑似重影、低支持区域或配准问题，建议下一步操作。
5. 查询任务状态、解释失败原因、保存可复用工作流和生成处理记录。

例如用户提出“把这几次扫描对齐，保留边缘细节”，Agent 应结合当前项目提出或执行可追踪的处理步骤，返回候选对齐、局部预览和参数记录。对称物体是否对错方向、细节是否被磨平等问题，需要让用户能够直观看到并修正。

Agent 上下文使用对象标识、统计摘要、标定/位姿说明、质量报告和必要预览，不将整份海量点云转换为文本。工具参数应具有类型、范围、输入版本和作用范围约束；几何数值计算由后端完成。

## Agent 框架的最小组成

- **项目上下文**：当前物体、扫描来源、选择区域、结果版本、已知单位/坐标和历史。
- **工具注册**：统一命令的参数说明、前置条件、返回结构与错误。
- **规划与执行**：组织步骤、提交任务、获取状态、处理失败和取消。
- **结果观察**：读取报告、预览和版本差异，再决定继续、调整或请用户作几何判断。
- **过程记录**：关联用户意图、工具调用、参数、输入和输出，允许检查与复现。

首版不要求 Agent 任意执行系统命令或生成即运行的几何代码。已有处理命令跑通后，再接入模型调用，可以独立验证工作流和 Agent 的作用。

## 验证目标

选取实际的多扫描失败案例，比较手工操作、固定工作流和 Agent 辅助三种方式完成同一任务的结果与耗时。评价处理成功率、所需交互次数、错误恢复、结果可复现性，以及接缝/重影等几何问题。

Agent 的有效性应体现在帮助选择和完成合适的处理步骤；模型回复流畅或单个配准残差变小，都不能单独证明重建更好。

当前已有旧四份工程和新增29份工程的解析、独立及多工程深度融合，以及通过与拒绝的配准候选。九类工具已注册，任务执行、输入版本核对、依赖产物核对、失败中止、步骤间取消与审阅页均已形成原型；Web界面已接入模型选择、局部查看、对应点核对与任务记录，工程历史、通用原帧重融合桥接和语言模型服务继续开发。旧书本案例与新工程的格式和坐标约定分别验证，不推广单一假设；其他工程若缺少位姿，仍应显式保留未知。
