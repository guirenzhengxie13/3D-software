# 对应点到原帧重融合：下一阶段约束与接入点

2026-10-21更新：下述单工程桥接已实现，CLI、固定工作流和114帧真实复现见 [当前实现与使用方法](fragment-fusion-bridge.md)。网页帧归属编辑、跨工程绑定与撤销历史仍待完成。以下保留2026-10-20的原始设计约束。

本记录原为2026-10-20续接研究结论。现有 `apply_landmark_alignment.py` 只保存对齐表面和变换；`reconstruct_fragment_plan.py` 已能按显式帧归属重新积分原始深度。两者不能通过PLY文件名或几何相似度自动认定为同一来源。

## 建议的最小闭环

1. 保留对应点核验输出的 `summary.json`、原会话、模型SHA和所选候选标签。候选必须唯一，变换须为毫米刚体变换；已有候选还要核对记录文件原字节SHA。
2. 另建显式来源绑定文件，至少记录 `scan_id`、原始 `decoded/index.json` 的SHA、源/目标模型SHA、源/目标各自的原帧ID列表，以及两模型使用保存扫描坐标毫米系的依据和人工决定说明。
3. 校验所有帧属于同一索引版本、帧集合非空且不重复、选定深度和位姿存在。通用PLY本身不携带可靠原帧归属，不允许根据显示行号推断帧ID。
4. 生成标准片段计划：目标为根且校正为单位阵，源为子片段且使用对应点确认的源到目标变换。通过 `compile_fragment_plan` 核对完整帧归属和树结构。ROI继续在原保存坐标下决定，避免校正位姿后悄悄改变所选像素。
5. 将计划交给现有 `reconstruct_fragment_plan.py`，输出到新目录。保存姿态控制组使用完全相同的帧与ROI，每个选中帧只积分一次；核对输出帧数和选中深度摘要。
6. 工程历史分别记录“核验对齐”“建立帧绑定”“生成计划”“重融合完成”，撤销只切换派生版本，不删除或修改原件。表面重影减少、内部残差下降不能独自证明物理精度提高。
